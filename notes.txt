0x000000FF -- BLACK COLOUR

a + bi
(a) and (b) - real numbers
(i) - i^2 = -1 - imaginary number

Assosiate complex number (a + bi) to the f(z) = z^2 + c function

Two options for f(z) = z^2 + c:
1. Distance from 0 of the sequence get arbitary large. That means it blows up.
2. Distance is bounced (never larger than 2)

One definition of Mandelbrot Set - set of complex #'s c for which distance
is bounced

How to draw a picture whether (c) is in the Mandelbrot set or not. 
Iterate 0 under z^2 + c , if it takes a long time to get big then you give it
one color, if it gets big really quicly you can give it a different color.

Mandelbrot set - it's a set of points C on the complex plane that doesn't
escape when you repeatedly apply this formula. 

3 + 2i actually means itself that the point is shifted 3 units to the right and
2 units up. 

A sequence diverges when it doesn’t settle down — when the values shoot off
toward infinity instead of approaching a limit.

Every point that never diverges (stays bounded/never goes to infinity) is part
of the Mandelbost set - it's therefore colored black.

___________________zooming in and out the fractal_____________

We want the point under mouse before zoom to stay the same after zoom,
so we adjust the offset to compensate.

x - pixel position of your mouse from the left edge of the window
y - pixel position of your mouse from the top edge of the window

(x / fractal->zoom) - converts pixel into complex-plane units

(x / fractal->zoom + fractal->offset_x) - the point in the complex plane that
corresponds to the mouse's current pixel

(x / (zoom * zoom_level)) - how much the coordinate under your mouse would shift
because zoom made each pixel smaller

______________________________MANDELBROT__SET___________________________________

Mandelbrot fractol is an escape-time fractal. The system that recursively iterate
over the input and try to find if the result stays within some bound (does not
escape in some certain number of iterations).

In order us to have more than just 2 colours for the fractal, we would need to use 
the numebr of iterations a point went through before escaping the set.

i^2 = -1

The higher the maximal number of iterations, the more detail and subtlety emerge in
the final image, but the longer time it will take to calculate the fractal image.

We stop iterations (detecting escapes) by determining the absolute value, or modulus, 
of the complex number. If this value, exceeds 2, or equivalently, when the sum of
squares of the real and imaginary parts exceed 4, the point has reached escape.

Escape_check = fractol->z_real * fractol->z_real + fractol->z_img * fractol->z_img;

Calculating the iteration counts associated with each pixel stores in
array: IterationCounts[x][y], where x and y are coordinates of a pixel in the window
respectively. 

#define BASE_R 27
#define BASE_G 219
#define BASE_B 226
#define BASE_A 255  // or 204 for 0.8 opacity

if (i == fractal->max_iterations)
{
    // Inside the set — black
    put_color_to_pixel(fractal, x, y, 0x000000FF);
}
else
{
    // Compute a brightness factor between 0.3 and 1.0
    double t = (double)i / fractal->max_iterations; // 0 → far away, 1 → near boundary
    double brightness = 0.3 + 0.7 * t; // never fully black, never overbright

    uint8_t r = (uint8_t)(BASE_R * brightness);
    uint8_t g = (uint8_t)(BASE_G * brightness);
    uint8_t b = (uint8_t)(BASE_B * brightness);
    uint8_t a = BASE_A;

    uint32_t color = (r << 24) | (g << 16) | (b << 8) | a;
    put_color_to_pixel(fractal, x, y, color);
}

if the pixel escapes really instantly -> t near 0
If the pixel survives almost to the end -> t near 1

________SQUARE OF A COMPLEX NUMBER FORMULA___________

(x + yi)^2 = (x + yi) * (x + yi) = x^2 + xyi + xyi + y^2i^2 = x^2 +2xyi - y^2
OR
x^2 - y^2 + 2xyi

x^2 - y^2 - real number
2xyi - imaginary part
